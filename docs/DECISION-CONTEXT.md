消息展示更新：完整原文及复制内容已改成可读消息，单元与模拟器 UI 验证通过，新版已覆盖安装到真实 iPhone。恢复 USB 与手机 Tailscale 连接后，更新后的长问题和长命令真机复验均通过：直接核对原始消息首行与长内容末尾，确认不再展示原始参数 JSON 区块，再验证原调用的实际回复与拒绝结果。此前测试控制通道未建立和手机 VPN 未连接的尝试不计为通过。临时验收请求和身份已清理。

## 数据来源与边界

新增可选 `decisionContext:{taskGoal,blockingReason,impactScope,originalContent}`，各项可缺失或为 null。机器沿用鉴权绑定的 hostId，项目沿用 projectPath。Codex 命令审批从原调用取得 cwd、command 和 reason；采集主机可用已关联会话的项目路径补齐 projectPath。Claude 从原 hook 取得 cwd、工具名和完整工具输入。

当前原生采集没有可核实的完整任务目标、完整影响范围，二者明确保留 null；Claude hook 也没有独立阻塞原因。界面显示“未知”，不把工作目录、工具描述或会话标题当作这些信息。已提供的结构化值可直接展示，但产品不根据命令自动推断所有文件、网络或部署影响。

`originalContent` 是面向决策的原始参数 JSON：Codex 保留完整问题数组（含选项说明），或命令、工作目录、理由与已提供的执行环境、操作类型、解析动作和权限／网络上下文；Claude 保留工具名、工作目录和完整 tool_input。JSON 转义不改变字符串内容，不截短命令或问题。host 专用 native 及其传输身份不整体导出；无法核实完整差异的文件审批继续留在原生界面。新增导出内容继续经过现有敏感输入检查。

## 手机查看与回复

原文页始终可用，包括已回答、过期和失效请求。原文页展示可读消息：问题按原顺序展示完整题文和选项说明，命令保留原始换行，工具参数按字段名称、值与层级展示；界面和复制内容均不附加序列化 JSON 包装。通用工具中名为 questions、id 或 prompt 的参数仍完整保留，不误当作原生提问路由信息。原始绑定内容保持不变。原文按行和有界长度换行显示，支持滚动、选择以及复制全部消息；布局换行不改变复制内容。新原文缺失时，旧请求展示全部已存正文、操作内容、问题和选项，旧版工具正文中的参数包装也转为可读字段，并明确说明独立原文未知，不能确认所有原生参数均已保存。

新增上下文、项目路径和会话标签参与新请求的 bindingDigest，旧上下文不能沿用到不同决策。没有 decisionContext 的历史请求保持原指纹算法，兼容在途答案。Widget 只有在全部新增决策内容已由其正文和选项表达时才允许直答；额外权限、选项说明或无法核对的原文要求进入 App 查看。

部署时须先升级 relay 的指纹算法，再启用新版 host 采集；仅升级 host 而保留旧 relay 不支持新增上下文请求的分步证明。旧请求继续使用原指纹。

## 验证

测试使用人工构造的公开示例，无真实机器、路径、任务或凭据。Rust 覆盖长命令、全部问题与选项说明、Claude 工具参数、敏感内容留在原生端、旧指纹兼容，以及上下文变化拒绝旧答案。Swift 覆盖 Codable／缓存往返、未知值、已回答旧题回看、Unicode 长原文保留及 Widget 入口判断。

iOS 模拟器 UI 检查完整请求上下文字段、缺失值及长原文消息末尾，并回归原有选择、文字回复、多选和分步回执。2026-10-22 本地结果：Rust 全量 137 通过、3 条件忽略；收件箱 UI 10 项通过。消息展示改进后，iOS 单元 139 通过、6 条件跳过，长原文 UI 回归通过；新增覆盖通用工具嵌套参数、备用 prompt、旧版工具正文及可读复制内容。格式检查及独立代码审查通过。

## 生产部署与真实 iPhone 验收

生产发布先经三台 host 的 prepare-upgrade 守卫确认排空，再备份 relay 数据库、配置及服务入口，安装独立新产物；relay 就绪后才切换 host。host 状态和配置、旧服务入口及旧产物保留用于恢复。发布中遇到运行时 IPC socket 的备份问题和慢链路传输超时，失败尝试自动恢复旧入口及原采集状态；排除非文件 IPC、改用压缩传输后完成切换，失败尝试不计为验收通过。

最终从运行进程核对 relay 与三台 host 的产物 SHA-256，均与本轮构建一致；relay 鉴权健康检查通过，三台 host 完成 startupReconciled 且恢复采集，host 配置字节保持不变，relay 配置在移除临时身份后与发布前语义一致。原生二进制和 App／Widget 运行时代码均经构建路径检查；App／Widget 严格签名、已有 team、目标设备 profile、共享 App Group 和 APNs 环境检查通过。手机覆盖安装，保留原产品身份、配对和服务器地址。

验收使用真实 Codex 原生进程、生产 relay、现有正式手机配对及实体 iPhone 上的原生 XCTest；模型输出由隔离的本地确定性 provider 构造，问题与命令均为无副作用示例，不调用外部模型或操作用户正在进行的任务。
