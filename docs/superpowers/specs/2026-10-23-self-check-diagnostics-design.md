# 一键自检与脱敏诊断

用户已确认第 5 项设计：按主机、适配器／采集、中转、同步、回传分段检查；测试推送和测试回复分别记录；原调用的独立接收证明是回复闭环的成功门槛。

## 协议与状态

复用已有鉴权、host 绑定、请求／答案版本绑定、持久回执。新增独立诊断状态与测试作业表，不修改正常任务。host 心跳报告固定枚举、计数和最近成功采集时间；未观察到 Claude hook 事件只能标为未知，不能凭主机心跳宣称 hook 已安装。旧 host／relay 缺少能力时显示未支持或未知。网络中断不把旧快照当作当前通过。

设备发起带幂等 ID、主机绑定及短期限的测试。host 原子领取，重启后不重启已领取测试。每台主机最多一个未过期测试；过期测试拒绝新答案。设备只能查看自己创建的测试，host 只能领取和更新自己的测试。

## 原生测试

首个自动支持组合是提供原生来源证明的 Codex app-server。host 在其独立私有测试目录创建全新 thread，并使用仅绑定 loopback 的固定 Responses 测试提供者。该提供者只产生一个固定的 request_user_input 和一条继续运行消息，不执行 shell、文件操作或外部模型请求。每次测试使用新的 thread／turn／call，沿现有生产采集、提交、仲裁及原文输出核对路径；测试线程不放宽正常目录采集范围。

通知排队、APNs 接受、手机观察到通知、同步取题、答案已提交、原调用已接收、任务已继续分别表示。接收与继续只来自已有 replyProgress 的精确原生证明。旧 adopted、socket 写成功、相同答案正文、APNs 成功不计接收。Claude 与未扩展 Codex 的自动原生测试显示未支持；保留各自采集观测状态，不能外推支持。测试失败与超时单独记录，不阻塞正常采集。

测试题正文固定且无敏感内容，推送仅发送给发起设备；测试请求不进入正常待办列表。通知观察仅记录本次测试通知，手机主动查询收件箱不能冒充 APNs 送达。

## App 与导出

设置增加“一键自检”：展示阶段、检查时间、固定错误分类与处理建议；每台主机可启动测试推送／回复。原生题就绪后在诊断页显示固定选项并通过现有 ReplySubmission 提交，不自动代用户回答。

诊断界面可使用本机已授权身份定位主机；分享使用独立白名单模型，仅包含 schema、应用版本、系统主版本、固定阶段／原因码、计数、耗时和报告内临时编号。禁止携带真实主机／设备／请求／会话标识、URL、IP、项目路径、题目／答案、原生证明、凭据、任意错误文本或原始日志。未知远端字段和错误分类不能透传到分享文本。

切换中转或配对后丢弃诊断与在途结果；操作期间禁用重复启动，超时后只读对账。分享动作由用户触发。

## 验证与交付边界

Rust 测试覆盖心跳新旧兼容、作业归属／幂等／过期／领取、独立接收与继续、推送归属和固定测试提供者。Swift 测试覆盖分类、敏感值污染后的白名单导出、未知字段、切换中转的旧结果丢弃、通知与接收独立。运行 Rust 全套、iOS 单元与诊断页 UI 测试。实际原生引擎可用时执行隔离闭环；模拟器推送不能代替真实 APNs／iPhone 验收。部署、真机安装与现场验收状态分别报告，未执行不记完成。
