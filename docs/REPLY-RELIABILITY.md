# 回复可靠闭环 · 2026-10-22

分步协议、持久恢复、防重复派发和可选 Codex 原生来源扩展已实现。生产 relay 已升级，真实 iPhone App 和 Widget 独立验收均通过；第 2 项按下述实际支持组合完成。现用 Codex/Claude 没有被替换，未提供来源证明的组合仍明确显示“来源未确认”。完整来源、部署和实测边界见[原生回执核查](REPLY-NATIVE-PROOF-AUDIT.md)。

## 三步语义

| 界面步骤 | 必需依据 | 不足以推进的现象 |
|---|---|---|
| 已提交 | relay 事务保存确切 requestId/responseId 的答案及 submitted | 本地 journal、发出 HTTP |
| 原调用已接收 | 原生仲裁胜者文件、完整原绑定和原调用结构化输出三者一致 | socket 写入、resolved、答案文字相同、仅有胜者文件 |
| 任务已继续运行 | 已验证接收之后，同一原执行链的后续进展 | 仅已接收、helper 成功、自然语言 marker |

当前可归属的正向路径是显式启用 [`native/codex`](../native/codex/README.md) 的隔离 Codex app-server。原答案不加入伪题、隐藏字符或自然语言标记。未扩展 Codex 与当前 Claude 只有内容匹配时仍报告 `nativeObservation=answerSourceUnconfirmed`，兼容旧 adopted 生命周期，界面不点亮新的接收或继续里程碑。

## 实现与恢复

- 固定字段、规范 JSON 和 SHA-256 绑定机器、引擎实例、原会话/轮次/调用、版本、题面和期限。错摘要、旧题、过期或冲突答案拒绝提交。
- SQLite 的答案和 submitted 同事务保存；received/continued 累积、幂等、不回退。continued 必须引用同一接收证明且处于其后。设备只取得阶段时间及解释，不取得原始证明或 transcript 路径。
- host 派发前 fsync 原请求、答案、输出前缀边界、原生实例和唯一 dispatch；至多领取/输出一次。旧输出、重写前缀、错调用或重复输出不产生新证明。
- 断线只重送 durable outbox 回执。重启只读核对旧胜者文件及原输出，不继承旧 callback；缺失边界或证明保持未知，不补发答案。
- 接收后观察继续运行，短暂读不到输出仍等待；超时或明确失败保留接收证明并解释 continued 未知。派发前失败持久记录后收敛，不无限等待不可能出现的原输出。
- 升级守卫计入活动 continuation、启动对账及 outbox；能力查询不明或网络失败不冒认就绪。旧守卫兼容聚合仍能看见待确认 continuation。
- App/Widget 共用阶段解释器；另一份获胜答案不显示为本地答案的成功。Widget 优先有效待答。前台 App 按当前场景状态只读刷新，取消结果不覆盖界面。
- journal 采用跨进程锁、私有文件、fsync 与原子 rename，绑定中继连接及配对代次。旧 defaults 记录只供核对；重试只能复用完全相同的 responseId 和答案，不能自动换 ID 重投。

## 支持边界

真实原生进程和生产 relay 使用本地确定性模型构造可暂停的无副作用问题，以便分别核验接收和继续。真实手机操作与两客户端协议竞答分别记录；没有把协议客户端叫作物理键盘，也没有把本地模型外推为外部模型服务。

未扩展 Codex、Claude、Linux 扩展引擎及桌面 App 嵌入扩展保持各自未支持/未验证边界。网络切换、物理键盘及全部启动入口的现场矩阵不因本轮通过而自动完成，继续归入需求第 6、7 项。第 2 项只按实际已验收组合结论收尾，不声明全部引擎已经具备来源证明。
